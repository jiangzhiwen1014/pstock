# 文档与独立需求版本

## 路径与事实来源

- 需求：`doc/requirements/PS-编号-标题/版本/`；实现设计：`doc/sprint/PS-编号-标题/同版本/`。
- 两侧 ID、标题、版本完全一致，需求 ID 稳定不复用；标题改名需两侧同步更新引用。
- 需求定义业务目标、规则与验收；详设引用需求，定义代码落点、接口、状态、数据与恢复。
- 架构维护系统基线和决策；详设记录采用的基线提交。不能用详设悄悄改变已确认需求。
- 每个需求根 README 记录版本索引和状态；sprint 根 README 记录实现入口和状态。

## 升版规则

| 情况 | 处理 |
|---|---|
| 草案整理、文字修订且业务不变 | 同版 Git 留痕 |
| 已确认需求的小范围业务修正 | patch 增长 |
| 兼容增加业务能力 | minor 增长，patch 归零 |
| 核心流程、数据语义或兼容边界重大变化 | major 增长，minor/patch 归零 |
| 代码没有实现原需求 | 修复代码，不自动升级需求 |

新版本保留完整可独立阅读的需求和相对上一版的变更说明；旧版本不删除。修订错字可改旧文档，不能把原先已确认的含义改写后冒充历史。

依赖必须写明 `PS-002@1.0.0` 等明确版本及所需能力；不使用“最新版本”作隐式依赖。

## 状态与交接

需求状态：骨架、草案、待确认、已确认、已废弃。骨架或草案不等于开发授权。详设状态：骨架、草案、待评审、可实施；由真实确认依据决定，不自动升级。

每项实施任务记录稳定任务 ID、前置依赖、允许文件、完成条件、执行人/模型、状态、提交和验证链接。状态明确待开始、进行中、阻塞、待验收、已完成。

换模型时更新任务拆分中的交接区：当前任务、实际改动、已验证内容、失败与阻塞、下一步。没有执行结果写未执行，不补填通过。模板见 [Skill](../SKILL.md)。
