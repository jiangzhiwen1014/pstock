# 后端开发规则

先读同版本详设与 [后端架构](../../../doc/architecture/后端架构.md)。语言、框架和数据库选型未确认时只维护架构骨架。

- 接口校验输入、授权、错误和输出；应用层实现用例/事务/幂等；领域层负责业务规则；仓储实现留在模块内。
- API 和 jobs 调用同一用例。跨模块流程由 workflows 组合公开接口；禁止直接写其他模块的表。
- 明确接口路径、方法、字段、错误、分页、幂等和兼容性，前后端引用同一契约来源；不重复手写多份权威契约。
- 资金与数量更新在详设中明确原子性、并发冲突和对账方式；重试不得重复记账。
- 外部调用设置超时和可恢复失败处理；不得吞错后返回成功。重试边界区分不可重试的参数/权限错误和临时失败。
- 涉及数据库变化时维护 migrations、兼容窗口和恢复步骤；无法反向恢复的数据迁移说明备份与前向修复方案。
- 日志记录可追踪任务或请求标识，脱敏账户和凭据。可观测记录不得暗含真实 Token。
- 准确数值、规则版本和时间定义遵守 [数据规则](data-rules.md)，领域计算不依赖模型自由文本。
