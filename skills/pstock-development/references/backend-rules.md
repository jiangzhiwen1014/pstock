# 后端开发规则

先读同版本详设与 [后端架构](../../../doc/architecture/后端架构.md)。采用 Python/FastAPI、PostgreSQL、SQLAlchemy/Psycopg、Alembic；任务初期使用数据库表和单 worker。精确版本在工程初始化时验证，技术基线确定不代表业务骨架已批准。

- 接口校验输入、授权、错误和输出；应用层实现用例/事务/幂等；领域层负责业务规则；仓储实现留在模块内。
- API 和 jobs 调用同一用例。跨模块流程由 workflows 组合公开接口；禁止直接写其他模块的表。
- 明确接口路径、方法、字段、错误、分页、幂等和兼容性，前后端引用同一契约来源；不重复手写多份权威契约。
- 资金与数量更新在详设中明确原子性、并发冲突和对账方式；重试不得重复记账。
- 外部调用设置超时和可恢复失败处理；不得吞错后返回成功。重试边界区分不可重试的参数/权限错误和临时失败。
- 涉及数据库变化时维护 migrations、兼容窗口和恢复步骤；无法反向恢复的数据迁移说明备份与前向修复方案。
- FastAPI/Pydantic 生成 OpenAPI 作为接口契约权威来源；同步 Session 不跨线程/请求/任务共享，阻塞数据库或 SDK 调用不得放入异步事件循环。
- 持久业务任务不能依赖进程内 BackgroundTasks；落实唯一幂等键、短事务领取、租约心跳、旧令牌保护、有限重试、断点恢复及通知不确定投递处理。业务写入和后续任务同事务保存。
- 初期低频批处理，后续可提高实时性；不要提前引入 Redis/RQ 或大规模微服务。任务接口与业务规则分离，增量处理与批处理必须保持一致口径。
- 按批次与窗口计算，后台初期一个执行槽；并发、锁与迁移在实际 PostgreSQL 验证。不得用 SQLite 通过来替代数据库行为验收。
- 日志记录可追踪任务或请求标识，脱敏账户和凭据。可观测记录不得暗含真实 Token。
- 准确数值、规则版本和时间定义遵守 [数据规则](data-rules.md)，领域计算不依赖模型自由文本。
