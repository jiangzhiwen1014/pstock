# 前端开发规则

先读需求同版本详设与 [前端架构](../../../doc/architecture/前端架构.md)。前端基线已确认，精确依赖版本、接口细节与行情主引擎仍需完成对应决策/验证。用户只要求文档落地时，不自行安装依赖或启动业务实现。

- 一个模块管理自己的 pages、components、api、state、types；简单组件不强制创建多层抽象。
- 服务端业务数据由 TanStack Query 管理；URL 状态、共享交互状态和组件临时状态按架构分工，不在 Zustand 复制持仓或行情缓存。
- 行情与综合图表分别封装，统一金融格式和生命周期；高频事件不得触发整个工作台刷新。主引擎候选不得当作已完成性能验收。
- 查询键包含账户、证券、周期和复权等影响结果的维度；切换身份清理相关缓存与订阅，旧请求不能覆盖当前页面。
- 请求使用统一客户端，避免页面直接访问外部数据源或自行附带供应商凭据。
- 页面数据来源、更新时间和缺失状态可见；研究标的与可交易标的清晰区分。
- 异步操作处理加载、错误、取消或过期响应、重复提交和离开页面后的清理；只在真实成功后展示成功。
- 准确数值使用服务端定义；前端只做展示格式和输入辅助，不能形成独立的收益或费用引擎。
- 模块之间通过公开接口协作，避免跨模块读取内部状态。shared 只放确有复用的内容。
- 新 UI 定义键盘操作、可读标签和适用屏幕范围；使用已确认的 Ant Design、CSS Modules 和设计变量；首次搭建时补充准确依赖与实际检查命令，不在未创建应用时写成已可运行。
- 定向测试覆盖真实行为。用户流程变更在服务和真实身份可用时进行浏览器验证；不可用时明确未验，不以静态截图代替实际流程。
