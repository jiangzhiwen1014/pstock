# PStock 模块边界

## 1. 围绕一份投资判断组织功能

业务闭环为：信息进入 → 数据质量检查 → 公司与外围影响研究 → 对照投资理由和账户风险 → 形成可观察的行动条件 → 记录用户行为 → 持续验证与复盘。

| 产品能力 | 核心目录（相对 `backend/src/pstock/modules/`） | 权威记录与边界 |
|---|---|---|
| 我的投资档案 | `profile/` | 交易权限、资金约束、投资周期、风险偏好；未确认参数保持未设置 |
| 数据与信息中心 | `market_data/` | 证券身份、交易日历、价格与财务口径、来源、可用时间、质量状态 |
| 公司与行业研究 | `research/` | 研究档案、证据引用、估值假设、行业对比与修订记录 |
| 外围影响分析 | `influence/` | 事件与行业/公司的关系、传导依据、反对证据、失效条件 |
| 策略研究中心 | `strategy/` | 因子定义、筛选规则、参数版本；研究候选与正式采用状态分开 |
| 持仓与账户 | `portfolio/` | 现金、持仓批次、交易记录、成本与账本计算规则 |
| 组合风险 | `risk/` | 基于账户快照计算集中度、共同暴露及风险结果，不反向改账 |
| 决策中心 | `decision/` | 买入理由、支持/反对证据、观察期限、触发与退出条件、用户动作 |
| 模拟与历史验证 | `simulation/` | 固定数据和规则的任务、订单、成交/拒绝记录；通过端口使用选定引擎 |
| 持续跟踪 | `monitoring/` | 关注条件、变化记录、提醒去重和冷却规则 |
| 长期复盘 | `review/` | 引用历史判断和结果快照进行归因，保留当时结论 |

报告属于这些模块的聚合视图：模块内 `application/` 与跨模块 `workflows/` 组织数据，`jobs/` 驱动生成，前端展示或通知适配器发送。报告不拥有另一份持仓或独立买卖结论。

## 2. 必须保持统一的约定

| 对象 | 约定 |
|---|---|
| 股票身份与权限 | 统一标识证券和市场；研究标的不等于可交易标的；交易计划及模拟入口再次校验权限 |
| 数据时间 | 区分事实所属时间、发布时间、首次可获取时间、采集时间和修订时间；历史验证按当时已知信息取数 |
| 数据质量 | 缺失、过期、来源冲突与失败单独记录；未知值不能当作零，核心数据不足时明确暂停相关结论 |
| 账户与账本 | 真实账户、持续模拟账户、单次回测账户使用相同规则和不同身份空间；禁止互相覆盖余额和持仓 |
| 规则与费用 | 交易、费用和公司行动处理使用有生效范围的统一版本；具体市场数值在实现前核对来源，不在页面硬编码 |
| 决策证据 | 关联证券、账户快照、数据快照、策略版本及支持/反对证据；新判断保留旧版本 |
| 数值与 AI | 金额、收益、费用及规则结果由确定性程序计算；模型用于解释与摘要，记录模型/提示版本；不可用时保留事实报告 |
| 持续运行 | 增量更新、有检查点、重试可恢复；采集、计算、推送各自记录幂等键和状态，重启不重复记账 |

提醒发送的外部系统未必支持严格一次交付。实现时明确处理发送成功但本地确认失败的情况，保留发送记录和恢复策略，不作无法兑现的“绝不重复”承诺。

## 3. 一次更新如何流转

1. 数据适配器取得新公告或外围事件，应用层保存原始来源、时间与质量结果。
2. `research/` 和 `influence/` 通过应用用例更新受影响的公司研究和传导假设。
3. `decision/` 对照原投资理由，`risk/` 根据同一账户快照计算变化，形成可追溯结果。
4. `monitoring/` 判定是否为实质变化，再由通知适配器投递；相同事件多条报道先归并。
5. 用户记录自己的动作；真实交易以确认的交易记录进入账户，模型输出不能自动写入成交账本。
6. `review/` 在观察期限到达或新证据进入时比较预期与结果，不覆盖历史判断。

## 5. 当前不预设的业务能力

自动实盘下单、多用户平台、高频交易、未开通板块交易和模型自动调整投资规则不在本次目录交付中。是否后续建设需单独明确需求。

资金规模、持仓周期、策略类型、风险阈值和数据预算保持待确认，不使用历史附件的示例值初始化用户档案。
