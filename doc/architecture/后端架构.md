# 后端架构

状态：2026-09-10 按用户授权落实后端技术基线；本次为文档与开发约束交付，尚未安装依赖、实现接口或部署服务。精确版本在工程初始化时固定。决策见 [ADR-003](decisions/ADR-003-后端技术框架.md)。

## 需求与选型依据

PStock 面向个人持续投研，交易范围为沪深主板，外围市场作为研究因素。前期重点是消息面、技术面、公司经营与竞争能力、持仓判断和复盘，采用定时采集与批量分析；后续迭代可能提高实时性，不把低频处理作为永久限制。资金、持有周期、风险阈值和精确更新频率仍待需求确认。

Python 的选择依据是数据采集、指标计算、策略验证与研究工具复用的衔接成本，不是未经测试的运行速度或内存优势。Java 可以完成业务功能，但当前没有足够需求收益支撑额外维护 Java 主应用和 Python 研究任务。开源组件按接口选择性接入，不合并多个完整应用或账本。

## 技术基线

| 能力 | 初期选型 | 职责与约束 |
|---|---|---|
| 语言与应用 | Python + FastAPI | 模块化单体，类型标注；接口与后台任务共用应用用例 |
| HTTP 运行 | Uvicorn | 初期一个 API 进程；生产禁止自动重载 |
| 输入输出与配置 | Pydantic + pydantic-settings | 显式校验，配置从运行环境注入，不把 ORM 对象直接作为接口契约 |
| 数据库 | PostgreSQL | 在用户允许 PG/MySQL 的范围内采用此前推荐的 PG；仅维护一个数据库实现 |
| 数据访问 | SQLAlchemy + Psycopg | 初期采用同步 Session、有限连接池；ORM 负责业务映射，批量操作可用 Core/参数化 SQL |
| 数据库迁移 | Alembic | 迁移脚本审查后独立执行；不在 API/worker 启动时竞争迁移 |
| 后台任务 | PostgreSQL 任务表 + Python worker | 初期一个 worker、一个执行槽；定时触发和任务执行分离，状态持久化 |
| 外部 HTTP | HTTPX | 超时、有限重试、限流与来源记录；按调用环境使用同步或异步客户端 |
| 数据计算 | NumPy / pandas 按功能引入 | 批量指标与分析；限制数据窗口，不在 API 请求中跑长回测 |
| 工程检查 | pytest、Ruff、mypy | 业务正确性、静态检查和类型检查；具体命令随工程初始化落地 |
| 日志与健康状态 | 标准 logging，结构化日志 | 请求 ID、任务 ID、数据时效、失败与耗时；健康接口不暴露凭据 |

SQLAlchemy 是应用内数据库工具，不是额外常驻服务。MySQL 不作为并行支持目标；若后续改选，需单独验证迁移、SQL 方言和任务并发语义。精确 Python/依赖版本、依赖管理工具及锁文件方案仍待兼容性验证；表中技术基线不表示已安装。

AKShare 为数据接入候选；回测引擎、Polars、Qlib 等在需求和样本验证后再选。外部大模型通过适配器调用，不在 4G 服务器上默认部署本地大模型。模型用于摘要、解释与证据整理；账本、费用、指标和收益由确定性程序计算。

## 模块内部

| 层 | 职责 | 依赖约束 |
|---|---|---|
| api | 接口、输入输出、访问控制入口 | 调用 application，不直接改表 |
| application | 用例、事务、授权与幂等流程；定义所需外部端口 | 调用 domain 和端口，不直接导入供应商 SDK |
| domain | 模型、业务规则、状态变化、计算 | 不依赖数据库、HTTP、API 框架 |
| infrastructure | 本模块仓储和其他技术实现 | 实现 application 定义的端口，由 bootstrap 装配 |

不为每个模块额外创建全局 ports 包；端口与其使用者归在同一模块。公共接入 `integrations/` 实现已定义的数据源、模型或引擎接口。

## 模块之间

跨域流程归 `workflows/`，只调用模块公开应用接口。每张业务表有明确模块归属，禁止跨模块直接写表。数据库连接等公共设施归公共 infrastructure，本模块查询和映射留在模块 infrastructure。

事务边界在详设中说明。涉及跨事务副作用时设计可重试、幂等和失败恢复，不能用一个“保存成功”掩盖外部调用失败。

## 运行入口

API 与 jobs 调用相同应用用例，禁止维护两套费用或记账规则。bootstrap 负责具体实现装配；jobs 负责触发、任务标识与重试，不复制领域逻辑。

FastAPI 路由与显式 Pydantic 请求/响应模型生成 OpenAPI，作为公开接口契约的权威来源。前端类型生成工具及产物路径在工程初始化时确定，不平行维护另一份手写权威契约。具体路径、分页、错误结构、认证方式和兼容规则由同版本详设确认。

同步数据库或阻塞 SDK 的调用应运行在同步路由/受控线程或 worker 中，不直接阻塞异步事件循环。需要 async 的外部 I/O 使用匹配客户端；Session 不跨线程、请求或任务共享。异步并不自动加速计算密集任务。长分析提交后返回任务身份，页面查询状态和已保存结果；FastAPI 进程内 BackgroundTasks 不承担要求持久恢复的业务任务。

## 初期任务与恢复设计

执行链：定时触发或用户请求 → 持久任务 → worker 领取 → 应用用例 → 保存结果 → 页面查询/通知任务。周期、交易日历、时区、过期补跑策略由需求配置，不硬编码原附件的小时和资金示例。

| 部分 | 必须落实的行为 |
|---|---|
| 定时触发 | worker 内独立轻量调度循环检查到期计划，执行计算不能阻塞触发与心跳；初期无需额外调度服务 |
| 入队 | 以任务类型、业务对象、计划时点或数据/规则版本形成唯一幂等键；重复触发不重复创建 |
| 领取 | 短事务内锁定并更新领取记录，可用 FOR UPDATE SKIP LOCKED；完成领取立即提交，不持锁执行网络或计算 |
| 状态 | queued → running → succeeded；可重试失败进入 retry_wait，到期重新排队；耗尽或不可重试进入 failed |
| 记录 | 任务 ID、类型、参数版本、业务引用、优先级、计划/可执行时间、尝试次数、租约所有者/令牌、租约到期、进度/断点、结果引用、错误摘要 |
| 租约恢复 | 心跳续租；失联任务租约到期后回收。完成更新校验领取令牌，旧执行者不得覆盖新尝试结果；恢复前核对已提交业务效果 |
| 超时与重试 | 外部请求超时；临时错误有限退避重试，参数和权限错误不盲重试。无法协作终止的计算由受监督子进程执行，确认旧执行停止后重试 |
| 一致性 | 任务按至少一次执行设计；业务唯一约束、幂等键和事务防止重复记账。业务落库与后续任务在同一数据库事务写入，保证不会保存后漏发任务 |
| 通知副作用 | 独立通知记录和去重键；利用供应商幂等能力。发送成功但本地确认失败时可能重复，不承诺外部恰好一次投递 |
| 优先级 | 日常消息更新与用户任务优先；历史回补/回测分批保存断点，在批次边界让出执行槽。优先级不能抢占正在运行的不可中断任务 |
| 结果发布 | 未完整完成的结果不替换上一份有效结果；页面展示生成时间、数据截至时间、覆盖率及失败状态 |

上述是必须落实的行为，不是已实现的表结构或调度器代码。共享任务表由 jobs/公共基础设施管理，业务表仍由各模块管理；不能仅有轮询循环而缺少租约、幂等和恢复。后续队列实现只能替换分发机制，业务幂等约束继续保留。

## 单服务器运行与资源

部署目标为持续在线的 4 核 4G 云服务器。初期运行静态前端入口、一个 API 进程、一个 worker 及一个 PostgreSQL 实例；同一后端构建产物使用不同启动入口。worker 如需隔离计算子进程，仅保留一个活动计算任务，纳入总资源预算。

- 按日期、证券批次、列和时间窗口读取数据，避免全市场多年历史一次进入内存；数据库连接池合计设置上限。
- 记录 API 延迟、任务等待/执行时长、进程峰值内存、磁盘增长与数据新鲜度。容量目标和任务时限按需求制定并实测，不编造可承载数据规模。
- 上线前落实 HTTPS、个人访问认证、数据库不公开暴露、持久卷/数据目录、日志轮转、进程重启和优雅停止。
- 备份存放服务器之外并验证恢复，迁移前备份；保留兼容版本和失败后的恢复路径，不以程序降级代替数据恢复。
- 服务器操作系统、磁盘和访问方式未知；Docker Compose 为部署候选，确认环境后落地配置。本轮不连接云服务器。

## 后续实时性演进

| 阶段 | 采用方式 | 扩展条件与验证 |
|---|---|---|
| 初期研究 | 定时采集、批量分析、结果持久化；页面查询/轮询 | 先验证信息质量、正确性、恢复与 4G 资源占用 |
| 提高新鲜度 | 部分来源提高轮询频率或增加订阅；事件触发增量分析 | 明确每类信息延迟目标与来源能力；验证乱序、重复、断连补齐、回补和重新计算 |
| 扩大吞吐 | 评估 Redis + RQ 或其他队列，按任务类别拆 worker | 数据库队列竞争或等待时间无法达标且定位到分发瓶颈；先压测、迁移和验证幂等，再切换 |
| 页面实时反馈 | 按场景增加 SSE 或 WebSocket | 有明确推送需求；实现鉴权、断线重连、快照补齐和背压；前期轮询作为降级路径 |
| 计算或容量扩展 | 优化算法/计算库、增加资源，必要时独立计算服务 | 性能剖析证明瓶颈；已有 4G 配置不保证满足后续实时目标 |

消息、行情、技术指标和财报研究分别设置更新节奏。接入层统一证券身份、来源、事件时间、接收时间和版本；批处理与增量计算共用领域定义。扩展不是只换队列：还需补齐顺序、幂等、回补及一致性验证。新增组件由 ADR 记录切换条件和回退方案，初期不提前实现所有实时设施。
