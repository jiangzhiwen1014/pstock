# 前端架构

状态：目录边界已确认；框架、组件库、状态库及接口类型生成方式待定。

采用业务模块优先：`modules/portfolio/` 管理账户页面及其组件、接口和状态。跨模块的页面组合交给应用路由或布局；业务模块通过稳定导出接口协作，不深层导入另一个模块的内部实现。

## 依赖边界

页面/组件 → 模块状态与 API → 公共请求客户端 → 后端公开契约。

- 页面只做输入、交互和展示；收益、费用、权限等结果以服务端权威定义为准。
- 模块专用组件、类型和工具留在模块；明确复用时再提取到 shared。
- API 客户端集中处理超时、认证和错误转换；模块解释业务错误，不能静默显示成功。
- 每个请求驱动的界面定义加载、空、错误、过期及权限不足状态。
- 证券页面明确区分研究标的与可交易标的；展示完整来源、时间与缺失状态。
- 配置、路由、契约生成与入口脚本在技术选型后追加，不创建假页面作为已实现证据。
