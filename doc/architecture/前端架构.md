## 2. 技术选型与职责

| 层次 | 选择 | 在 PStock 的职责与边界 |
|---|---|---|
| 页面框架 | React | 模块化页面和交互；不把图表高频事件提升为整页状态 |
| 语言 | TypeScript，严格检查 | 证券、账户、行情及接口数据类型；类型声明不代替运行时校验 |
| 开发与构建 | Vite | 开发服务、按路由拆包、生产静态产物 |
| 页面路由 | React Router | 页面导航、证券详情地址、查询参数 |
| 基础组件 | Ant Design | 表格、表单、日期、抽屉、提示；结合投研布局定制 |
| 行情主图 | Lightweight Charts，初选 | K 线、成交量、指标副图和信号标记 |
| 综合图表 | Apache ECharts | 收益、回撤、财务比较、行业分布、相关性与关系图 |
| 接口数据 | TanStack Query | 查询缓存、加载、失效、刷新及写操作后的缓存协调 |
| 共享界面状态 | Zustand，按需使用 | 跨组件联动、面板偏好；不复制服务端业务缓存 |
| 样式 | CSS Modules + 统一设计变量 | 模块样式隔离、色彩、字号和间距；与组件库主题协调 |
| 验证 | Vitest + React Testing Library + Playwright | 逻辑、组件行为和真实浏览器完整流程 |

采用电脑端优先的浏览器单页应用，前端静态部署，后端独立提供接口。暂不引入服务端页面渲染；若以后存在公开内容、首屏或搜索索引需求，再评估并记录新决策。

React、Vite、路由和数据层需要我们维护明确分工；本选型不意味着 React 的图表性能天然优于 Vue。[React 建设说明](https://react.dev/learn/build-a-react-app-from-scratch)、[Vite](https://vite.dev/guide/)、[React Router](https://reactrouter.com/start/modes)

Ant Design 用于基础交互，页面整体布局由 PStock 设计。第一阶段不引入第二套基础组件库或自由拖拽面板系统。[Ant Design](https://ant.design/docs/react/introduce/)

## 3. 状态归属与数据流

| 状态类别 | 归属 | 示例 |
|---|---|---|
| 后端业务数据 | TanStack Query | 持仓、财务、报告、历史行情 |
| 页面地址状态 | URL / React Router | 当前证券、周期、适合分享的筛选条件 |
| 跨组件交互状态 | Zustand | 图表联动分组、面板开关 |
| 单组件临时状态 | React 本地状态 / 表单组件 | 弹窗、尚未提交的输入 |
| 图表实例与高频缓冲 | 图表封装内部 | 十字线、绘图实例、增量队列 |

避免同一状态出现多个权威副本：当前证券如已由 URL 管理，其他模块读取路由上下文，不在 Zustand 再保存一份。后端返回的持仓由 Query 缓存管理，不另存入全局 store。[TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview)、[Zustand](https://github.com/pmndrs/zustand)

建议数据流：

1. 页面/路由确定证券、账户、周期和筛选条件。
2. 模块查询通过统一 HTTP 客户端访问后端；查询键包含证券、周期、复权方式等影响结果的维度，账户数据必须包含账户身份。
3. 写操作确认成功后更新或使相关查询失效；资金等关键状态不先假设成功。
4. 快速切换证券或账户时取消旧请求，或通过请求身份忽略过期响应，避免串数据。
5. 实时更新通过订阅管理与图表增量接口处理；需要更新业务缓存时在同一身份和时间口径下协调，禁止建立独立账本。
6. 注销或切换身份清理受影响缓存与订阅；不默认将账户明细、报告和凭据持久化到浏览器存储。

刷新和重试策略按数据类别制定，不能全站盲目使用相同频率。参数/权限错误不反复重试；旧数据显示时必须同时显示过期或刷新失败状态。

## 4. 图表封装

两类图表统一主题、时间、数值格式、数据质量展示、尺寸调整和销毁规则，保留各自引擎特点。

| 类型 | 封装位置 | 业务示例 |
|---|---|---|
| 行情图 | shared/charts/financial | K 线、成交量、指标副图、决策标记 |
| 分析图 | shared/charts/analytics | 账户收益、回撤、公司财务、行业分布 |
| 图表主题 | shared/charts/theme | 深浅主题、字体、颜色、提示格式 |

Lightweight Charts 提供金融图表基础能力和示例；复杂指标管理、画线及工具面板仍需核对实现成本。若用户依赖大量内置指标/画线，以同样的数据和交互样本比较 KLineChart，选定一个正式行情引擎，不同时维护两个生产主图。[Lightweight Charts 示例](https://tradingview.github.io/lightweight-charts/tutorials)、[KLineChart](https://github.com/klinecharts/KLineChart)

ECharts 承担综合图形，按实际图形按需加载。大数据图优先验证 Canvas，多实例小图结合内存结果比较 SVG，不能以官方通用性能描述代替本项目实测。[ECharts 图形](https://echarts.apache.org/en/feature.html)、[渲染器选择](https://echarts.apache.org/handbook/en/best-practices/canvas-vs-svg/)

行情适配接口围绕 PStock 的真实用例定义：首次数据、历史补齐、增量更新、标记、时间范围及销毁。避免把两类图表所有选项塞入一个万能组件。替换候选引擎时保持业务输入稳定，以固定样本核对显示结果。

## 6. 界面组织与金融展示

以电脑端投研工作台为优先。导航分组初案为今日、研究、持仓、策略验证、事件、复盘、设置，具体页面范围仍由需求定义。

顶部统一股票搜索、当前账户、时间范围和数据状态。主体按业务组合图表、列表与研究内容；抽屉承载事件来源和记录详情；证据区展示支持、反对和待观察条件。

- 深浅主题和信息密度通过设计变量管理；上涨/下跌颜色可配置，同时显示文字和数值。
- 定义键盘操作、焦点、标签及适用屏幕范围；电脑优先不等于任意窄屏直接溢出。
- 研究标的和可交易标的清晰区分，前端展示权限不替代后端校验。
- 数值由后端权威规则计算，前端负责格式化与输入辅助。图表自带指标需对齐口径，不能与正式策略各算各的。
- 区分交易日期与绝对时间点、交易所时区和浏览器时区；日线日期不随浏览器时区漂移。
- 所有数据驱动界面定义加载、空、失败、过期、缺失及权限不足状态。未知不显示为零。

## 7. 大量图表与失败恢复

- 按路由与可见面板加载图表代码；按时间范围加载数据，滚动时补齐历史，不一次传全市场多年分钟数据。
- 增量行情更新相关系列，不重建整个图表；高频缓冲不触发全工作台刷新。
- 同一证券和周期复用订阅，组件卸载取消订阅、事件监听、定时器与图表实例。
- 不可见页面按任务语义暂停或降频，恢复可见后核对时效。关键告警由后台负责，不能依赖浏览器标签一直打开。
- 断线重连要重建快照与后续增量的一致性，处理重复、乱序和缺口；具体协议与后端共同确认。
- 后端错误映射为业务可读信息；AI 不可用时保留已有事实和规则结果。
- 供应商和模型凭据不进入浏览器。认证、跨域、Cookie/Token 与请求保护随后端部署方案确定。
