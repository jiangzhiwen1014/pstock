## 开发者初始化

已有 PStock 工作区，在根目录运行：

```sh
git submodule update --init --recursive --checkout
git submodule status
git -C third_party/a-stock-data status --short
```

首次克隆当前交付分支：

```sh
git clone --recurse-submodules --branch codex/docs-directory-layout https://github.com/jiangzhiwen1014/pstock.git
```

后续若已合入默认分支，可省略 `--branch`。首次初始化需要访问 GitHub；网络代理按开发者已有环境提供，不在仓库记录个人代理或凭据。子模块缺失时提示初始化，不能悄悄改用远端最新版。普通 `git pull` 后也应执行初始化命令，使本地子模块与父仓库固定提交一致。

成功标准：子模块状态没有 `-`（未初始化）、`+`（提交不匹配）或 `U`（冲突）前缀；子模块工作区没有修改。这里仅验证版本恢复，不验证金融数据接口。

## 升级流程

1. 明确需要修复或新增的取数能力。在 PStock 当前获批功能分支操作，保留并检查已有修改。
2. 记录旧 gitlink 和拟采用的完整新提交。先获取上游，再比较旧、新提交的 CHANGELOG、相关代码块、共用辅助函数、依赖、许可证和测试。
3. 逐项判断是否影响已使用能力。将旧上游、新上游与 PStock 适配模块三方比较；新功能不自动成为一期需求。
4. 按获批范围迁移改动，保持 PStock 字段、单位、证券身份、时间口径稳定。已补的分页、错误分类和质量检查不能被上游更新覆盖。记录每个适配模块的新来源提交及本地差异。
5. 在独立验证目录完成受影响的契约检查和真实取数样本验证。覆盖相关板块、历史区间、复权与金额单位、分页总数、空结果与接口失败；上游测试通过不能替代这些检查。
6. 验证通过后，将子模块切至审定的新提交，以 detached HEAD 保持版本明确。同一 PStock 提交包含 gitlink、适配改动、来源清单、本表和验证证据引用。

查看差异的命令如下；`OLD_SHA`、`NEW_SHA` 是待替换的完整提交占位符，不直接照抄执行：

```sh
git -C third_party/a-stock-data fetch origin
git -C third_party/a-stock-data diff OLD_SHA NEW_SHA -- SKILL.md CHANGELOG.md LICENSE tests
git -C third_party/a-stock-data checkout --detach NEW_SHA
```

日常初始化不使用 `git submodule update --remote` 或在子模块内 `git pull`。父仓库的固定版本变更须与适配和验证一起审查。Git submodule 负责追踪版本，不承担自动移植或兼容性判断。
