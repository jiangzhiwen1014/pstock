# 数据架构

状态：初期数据库采用 PostgreSQL，SQLAlchemy/Psycopg 管理访问，Alembic 管理迁移；数据责任与关键语义已规划，尚无物理表、数据源接入或迁移脚本。运行与任务规则见 [后端架构](后端架构.md)。

| 数据域 | 所有者 | 必需语义 |
|---|---|---|
| 投资档案 | profile | 权限、偏好、未设置状态；不使用未经确认的参数 |
| 证券和行情事实 | market_data | 稳定证券标识、来源、市场、口径、时间、修订、质量 |
| 研究及传导关系 | research / influence 各自记录 | 支持与反对证据、关联对象、有效期和失效条件 |
| 账户、现金及持仓批次 | portfolio | 账户身份、批次、统一规则版本、可对账记录 |
| 策略与模拟运行 | strategy / simulation 各自记录 | 策略版本、固定数据快照、运行 ID、成交/拒绝原因 |
| 判断与复盘 | decision / review 各自记录 | 原始假设、当时证据、用户动作与后续结果；不覆盖旧判断 |

## 存储边界

账户、交易、证券身份等核心记录使用显式关系模型和约束；金额采用 Decimal/NUMERIC，精度、舍入和数量规则由详设确定。JSONB 仅用于适合演进的外部元数据或任务参数，不替代核心账本字段与约束。大体积原始附件可保存于仓库外的持久文件目录，数据库保存来源和引用，纳入备份策略。

任务状态与结果引用保存在同一 PostgreSQL 实例，业务变更与后续任务写入需要原子提交时使用同一事务。结果保留数据快照/版本、规则版本和模型配置引用，部分失败不可覆盖上一份有效分析。配置引用不包含密钥。

初期不增加第二套分析数据库、独立缓存或向量数据库；确有检索或计算需求后再评估。来源字段、事件时间、采集时间和修订版本为后续增量处理与回补提供依据。

## 实现前必须落实

区分事实时间、发布时间、首次可用时间、采集时间与修订时间。历史计算只能读取该时点已知信息。缺失、过期、冲突不能变成零值。

真实、持续模拟及每次回测各自隔离持仓和现金。同一规则和版本的费用、交易约束和公司行动计算必须可复现。市场具体数值与生效日期需要单独核对，不在此规划硬编码。

原始数据、规范化数据与衍生结果保留来源链；先设计幂等键与修订策略再接入。个人账户数据、原始抓取结果、报告和缓存不得进入 Git。

物理模型与迁移在对应 [开发详设](../sprint/README.md) 落地，并引用 [数据规则](../../skills/pstock-development/references/data-rules.md)。
