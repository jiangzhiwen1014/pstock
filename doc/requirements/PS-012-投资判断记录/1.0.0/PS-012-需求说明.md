## 目标与场景

让我保存当时为什么关注或持有、哪些证据支持/反对，以及后来有没有得到验证，避免用今天的资料改写过去。

## 主流程

从公司/事件创建判断卡 → 写理由与证据 → 设置观察事项 → 保存当前版本 → 新证据出现后复核 → 写修订理由 → 归档并回看。

入口、跨功能要求及一期容量见 [一期总览](../../V1.0.0-一期需求总览.md)。所有个人投资参数未确认时保持未设置；提到的容量/指标/时刻为产品建议值，不是已知用户事实。

## 数据对象

判断 ID/版本、证券、关联账户快照、创建/修订时间、理由、支持/反对证据、观察期限、失效条件、用户状态、复核记录。

对象字段为业务语义，物理表、接口路径、错误代码和索引由同版本详设确定。来源、质量与版本语义遵守 [数据架构](../../../architecture/数据架构.md)。

## 业务规则

| 规则 ID | 规则 |
|---|---|
| PS-012-R01 | 判断卡支持观察、持有理由、待复核、已归档状态；状态由用户确认，系统只能标记待复核线索，不能自动把观察变成买入或修改真实持仓。 |
| PS-012-R02 | 保存至少填写公司、判断理由和一项待观察事项；支持/反对证据可以暂缺但必须显示缺口。投资期限、目标价、风险阈值不强制填写、不自动填示例。 |
| PS-012-R03 | 证据引用固定来源版本、发布时间、采集时间与原文定位；引用研究、技术或持仓快照时固定对应版本，不使用动态最新值重建旧卡。 |
| PS-012-R04 | 新证据与已有判断有确定证券/关系匹配时形成待复核线索，明确关联原因；模型建议与用户确认分开记录，不自动判断假设已经成立或失效。 |
| PS-012-R05 | 观察期限可为空；到期仅生成站内复核事项，不自动要求交易。用户可标记支持、削弱、证据不足或待观察，并填写说明。 |
| PS-012-R06 | 修改保存新版本和修订原因；并发编辑旧版本须提示冲突并保留用户输入，不能静默覆盖；重复提交同一保存结果不重复建版本。 |
| PS-012-R07 | 复盘按原判断、当时证据、后续事件和用户评估并排展示；一期不计算策略胜率或把股价上涨自动归因为研究正确。允许结论不确定。 |
| PS-012-R08 | 支持归档/恢复、历史版本浏览和本人结构化导出；归档不删除被报告引用的证据。缺失原文时保留来源身份和不可访问状态，不展示伪造全文。 |

## 正常与异常结果

- PS-012-AC01：系统发现负面事件后创建复核提示，原持仓数量和用户判断状态不被擅改。
- PS-012-AC02：无理由时不能保存；没有反对证据时保存成功但显示尚未补充反证。
- PS-012-AC03：修改持仓或财报更正后，旧卡仍能显示当时快照。
- PS-012-AC04：消息仅提同一行业时说明间接关联，不能直接标为公司原假设失效。
- PS-012-AC05：期限到达后显示待复核，延期保留原期限与修改原因。
- PS-012-AC06：两个页面同时编辑，后保存者得到冲突提示；双击不会增加两个相同版本。
- PS-012-AC07：股价上涨但经营假设未验证时仍可标记证据不足，没有自动成功标签。
- PS-012-AC08：归档卡在旧报告中仍可查看；原文失效显示无法访问及保存的来源信息。

这些结果定义预期行为，执行步骤与规则映射见 [验收标准](PS-012-验收标准.md)，当前均未运行。

## 本期边界

自动交易计划执行、仓位建议引擎、收益归因、胜率排名和自动修改投资规则不纳入一期。

原方案中超出本期的能力保留为后续候选，不以缩减一期方式删除历史编号。前端、后端和后台任务必须共享相同事实与规则。

## 状态、隐私与恢复

本人数据和导出需认证。新增/修改需明确反馈，失败不覆盖旧有效结果。归档与删除语义按上述规则执行；源数据修订与用户记录版本分离。日志和导出不得包含密钥，外部文本不构成可执行指令。

## 待评审与交接

本稿功能范围和产品建议值待用户确认；数据源实际覆盖、部署配置和性能目标待验证。不得把这些待确认事项改写为已通过。确认后同版本详设应逐条映射规则与验收，不得绕过需求新增自动交易、付费来源或外部通知。
