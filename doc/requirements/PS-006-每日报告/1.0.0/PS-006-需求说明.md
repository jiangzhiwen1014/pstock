## 目标与场景

让我每天在一个入口看清重要变化、关注对象和待复核判断，并能展开核验证据。

## 主流程

到达配置时间或用户请求 → 确定截至时间 → 汇总当前可用快照 → 生成事实与分析 → 校验引用 → 发布报告版本 → 用户展开查看/复核。

入口、跨功能要求及一期容量见 [一期总览](../../V1.0.0-一期需求总览.md)。所有个人投资参数未确认时保持未设置；提到的容量/指标/时刻为产品建议值，不是已知用户事实。

## 数据对象

报告 ID、业务日期、截至时间、生成时间、触发方式、状态、快照引用、来源覆盖、模型/提示版本、修订记录。

对象字段为业务语义，物理表、接口路径、错误代码和索引由同版本详设确定。来源、质量与版本语义遵守 [数据架构](../../../architecture/数据架构.md)。

## 业务规则

| 规则 ID | 规则 |
|---|---|
| PS-006-R01 | 提供今日页和历史报告页，固定包含数据健康概览、持仓/关注变化、重要消息、公司研究变化、技术观察、待复核判断六部分；没有持仓时以关注公司为主。 |
| PS-006-R02 | 每条变化链接到公司、事件或判断卡的具体版本，并同时展示事实、解释和待观察事项；报告只聚合已有权威结果，不维护第二套持仓、指标或评分。 |
| PS-006-R03 | 重要消息按已解释的关联和变化排序；没有新变化时简洁说明，不强行生成利好利空或每日前10买入名单；限制默认摘要条数，完整列表可展开。 |
| PS-006-R04 | 每天固定时间可配置，默认建议北京时间交易日18:30，用户确认前标记为建议值；按需刷新生成新版本。数据不齐也可生成部分报告，但标明缺项和截至时间，不伪装完整。 |
| PS-006-R05 | 状态包含等待、生成中、完整、部分、失败；按账户/业务日期/输入版本保证重复触发幂等。失败保留上一份有效报告，新生成内容校验通过才发布。 |
| PS-006-R06 | 模型不可用时仍生成事实和确定性规则报告，明确推断未生成；引用不匹配或数值与源结果冲突时拒绝该分析段并展示事实。 |
| PS-006-R07 | 一期必交付为站内报告和本人 Markdown 导出，默认不外发。导出包含截至时间、来源链接和质量标记，不包含密钥；报告历史至少保留所有被判断卡引用的版本。 |
| PS-006-R08 | 支持对任一报告查看数据输入范围、生成时间和失败摘要；关注变更从下一次生成生效，历史报告不因清仓/归档自选而改写。 |

## 正常与异常结果

- PS-006-AC01：零持仓但有自选时仍生成可用简报；无关注对象时引导设置范围，不随机推荐股票。
- PS-006-AC02：同一快照的持仓数值在报告与持仓页一致；引用能返回当时版本而不是最新状态。
- PS-006-AC03：当天无实质变化时报告明确无新增且展示覆盖情况，不编造新投资机会。
- PS-006-AC04：盘后来源延迟时发布带缺口的报告，补齐后新版本保留旧版；非交易日不凭空生成新行情。
- PS-006-AC05：重复点击生成不出现重复任务；模型或分析失败不会将旧报告替换为空页面。
- PS-006-AC06：模型把100写成1000时，该段不能作为有效结论发布，事实区仍显示100。
- PS-006-AC07：导出内容与查看版本一致且不泄露配置；未登录访问报告和导出均被拒绝。
- PS-006-AC08：删除普通关注后旧报告仍可解释当时为何包含该公司。

这些结果定义预期行为，执行步骤与规则映射见 [验收标准](PS-006-验收标准.md)，当前均未运行。

## 本期边界

周报、盘中实时播报、外部推送渠道和自主买卖建议留待后续需求，不以模型文案替代确定性计算。

原方案中超出本期的能力保留为后续候选，不以缩减一期方式删除历史编号。前端、后端和后台任务必须共享相同事实与规则。

## 状态、隐私与恢复

本人数据和导出需认证。新增/修改需明确反馈，失败不覆盖旧有效结果。归档与删除语义按上述规则执行；源数据修订与用户记录版本分离。日志和导出不得包含密钥，外部文本不构成可执行指令。

## 待评审与交接

本稿功能范围和产品建议值待用户确认；数据源实际覆盖、部署配置和性能目标待验证。不得把这些待确认事项改写为已通过。确认后同版本详设应逐条映射规则与验收，不得绕过需求新增自动交易、付费来源或外部通知。
