## 目标与场景

为一期所有页面提供来源明确、时间可查、缺失可见的数据，避免多个模块对同一事实各算一套。

## 主流程

核对固定上游及能力覆盖 → 验证并登记可用适配 → 配置数据集与允许来源 → 首次分批补齐 → 校验标准化 → 保存来源与版本 → 生成分析就绪状态 → 定时增量更新 → 失败重试或补采。

入口、跨功能要求及一期容量见 [一期总览](../../V1.0.0-一期需求总览.md)。所有个人投资参数未确认时保持未设置；提到的容量/指标/时刻为产品建议值，不是已知用户事实。

## 数据对象

证券、交易日历、行情、复权信息、财务记录、公告文档、采集任务、来源能力、质量结果；保留事实时间、披露时间、首次可用时间、采集时间、修订版本和单位。

对象字段为业务语义，物理表、接口路径、错误代码和索引由同版本详设确定。来源、质量与版本语义遵守 [数据架构](../../../architecture/数据架构.md)。

## 业务规则

| 规则 ID | 规则 |
|---|---|
| PS-002-R01 | 全A股公司为资料覆盖范围，包括沪深主板、创业板、科创板和北交所上市A股公司；公司可检索与资料覆盖不受是否自选或持仓限制。全量目标为基础资料、近3年可得日线、近5份可得年报/年度财务、最近8个已披露季度、近90天公告和可得近30天新闻。来源不足必须逐项标注，不预设所有公司资料齐全。 |
| PS-002-R02 | 免费来源优先，取数实现优先复用固定版本a-stock-data；真实供应方、允许用法、云端可达、市场/字段/历史覆盖、单位和调用限制必须逐能力验证。公告以巨潮/交易所为核验核心；AKShare仅作为未覆盖能力的补充工具候选，BaoStock按实际支持范围使用，不要求并行重复接入同一来源。 |
| PS-002-R03 | 证券以稳定身份绑定市场和板块，更名保留历史别名；不按简称合并公司。日期、币种、数量单位显式转换；保留原始字段，重复数据以来源、业务键和版本处理。 |
| PS-002-R04 | 日线的未复权、前复权和复权因子/版本明确区分；财务明确合并/母公司、累计/单季、报告期与实际披露时间。无披露时间的历史资料不得用于当时已知的判断重建。 |
| PS-002-R05 | 质量状态至少包含正常、缺失、过期、冲突、失败、不适用。数据集按交易日历和来源更新时间判定新鲜度；停牌/未到披露期与失败区分。核心输入缺失则相关计算不可用。 |
| PS-002-R06 | 原始披露保存原文链接、文档身份、获取记录；在来源允许时存档全文并校验内容。扫描件/表格解析失败保留原件入口和待核对状态，不把抽取错误当事实。 |
| PS-002-R07 | 增量采集记录游标并保留重叠窗口去重；任务失败可重试、重启可续跑。取数函数只返回第一页或有限条目时，适配必须核对分页总数与实际时间区间，按来源限额分批回补，不能把首次返回当作完整历史。区分无记录、解析失败和分页中断；取数与分析分离，来源频率独立于每日展示频率。 |
| PS-002-R08 | 同一字段冲突保留各来源及采用理由；备用来源切换须验证口径。指标必须记录源数据版本；页面展示最近成功更新时间、失败状态与覆盖范围。数据写 PostgreSQL，允许的大文档在仓库外存档并纳入备份。 |
| PS-002-R09 | 每次以固定基准日的上市证券名单核对全A范围，记录各市场应有/已建档/缺失/异常数。公司实体与证券分开，跨市场或多证券关联同一主体；新增上市、证券更名/换码、迁移板块可追踪，不能只靠当前代码前缀识别。 |
| PS-002-R10 | 资料目录至少覆盖公司基本资料、证券/股本、主营/收入构成、财务三表及指标、股东/实控人/管理层、分红融资回购、经营及重大事件、监管审计风险、行业/同行、日线技术、公告/投资者关系/新闻。每类记录来源、有效日期、可得字段和缺项；只保存公开公司资料及其专业职务信息。 |
| PS-002-R11 | 全量公司基础建档是验收前置；公司资料后台分批回补且可恢复，优先持仓/自选和当前打开公司，但低优先级全量任务持续推进并防止长期饥饿。按需触发只加速补齐，不能代替全市场回补任务。 |
| PS-002-R12 | 公司覆盖与资料完整度分别验收。当前上市A股目录按基准名单100%逐条对齐，异常名单未处理不能宣称目录完成；必需核心字段为身份/市场/板块/状态/名称，以及其可得最近有效行情和已披露财务。其他资料按数据类别列总数、覆盖数、时效和缺失原因，不用单一百分比掩盖核心缺失。历史退市公司按可得来源单列归档，不进入默认当前上市名单，也不在退市时删除已有历史。 |
| PS-002-R13 | 按数据类别、供应方、市场/板块、字段和历史区间建立能力登记，区分源码已引入、待适配、待验证、已验证可用、停用/失败；就绪状态须关联验证环境、日期与证据。已验证可用仅适用于记录的边界，不能由单只股票成功推断全A全部字段可用。核心能力未就绪阻止其被标为可交付；实际公司覆盖另按R09/R12全量核对。 |
| PS-002-R14 | 采集批次及标准化结果保留真实供应方、端点/查询范围、上游完整提交、PStock适配版本及原始证据引用；规范化与计算结果关联输入批次。公共数据由上游工具转接时不能把工具名称替代真实来源；修订产生新版本，不改写旧研究/报告的引用。 |
| PS-002-R15 | 取数代码经审查整理为确定的PStock模块，数据消费经标准化、质量校验及持久化；公司页、技术页、筛选和报告共用已入库事实。前端不直连供应方，应用运行时不执行SKILL.md，也不临时由模型生成抓取代码；上游自带缓存、示例文件和调度不另成一套生产数据中心。 |
| PS-002-R16 | 上游升级与适配版本绑定并记录受影响能力；字段、单位、证券身份、时间、分页与错误语义验证通过后才能启用新版。失败时保留旧有效结果和明确状态；回退同时考虑代码、配置及已写数据的受影响范围，必要时修复/重算，不能仅退gitlink便声称恢复。维护操作权限与个人私有系统一致。 |

## 正常与异常结果

- PS-002-AC01：新上市公司不足3年时展示实际覆盖；新闻来源只有短窗口时标记缺口，不伪造30天历史。
- PS-002-AC02：按能力选定取数实现并保留真实供应方与验证边界，不重复计为两个独立来源；需付费权限者未启用且不自动付费。
- PS-002-AC03：同名不同市场证券不合并；成交量手/股转换后可核对，重复采集不重复增加日线。
- PS-002-AC04：两个季度累计收入不被直接标为单季；后发布更正值不回写旧报告快照。
- PS-002-AC05：周末不会仅因未出现当天日线而报警；有效交易日超过配置宽限仍未更新会显示过期。
- PS-002-AC06：损坏 PDF 或解析失败不发布空财务值；用户可看到失败原因及仍可用的原文链接。
- PS-002-AC07：恢复后按业务键无重复、分页总数及可得区间可核对；第一页成功不代表历史完整，中断/不可回补区间明确提示。
- PS-002-AC08：主源失败时保留旧有效数据并标明时间；不同供应商复权值不能无说明拼成一条曲线。
- PS-002-AC09：基准日名单中每个当前上市A股证券均有可访问档案或明确异常记录；同一公司不重复建实体，更名换码保留关联。
- PS-002-AC10：每家公司有统一资料分类与覆盖状态；缺管理层或股权记录明确显示缺失，不用空白页代替；不采集非公开私人信息。
- PS-002-AC11：全市场待补队列有进度且未关注公司仍得到处理；恢复不重复，不能以仅50家公司有数据宣称全量完成。
- PS-002-AC12：漏公司使目录验收失败；资料缺失逐项有原因及补齐/范围评审记录；退市后历史仍可查但不出现在当前上市默认列表。
- PS-002-AC13：初始化只显示源码已引入；已通过和未通过能力分开登记，未通过能力不被用于相关计算或宣称全A齐全；全量目录验收仍独立执行。
- PS-002-AC14：每个结果可追到真实源、采集批次、上游与适配版本；修订可对照，旧研究与日报仍引用原输入。
- PS-002-AC15：已有事实仍可查询且显示时效，新采集明确失败；各入口引用相同批次和口径，不执行Markdown或绕过统一入库链路。
- PS-002-AC16：未验证版本不投入使用，旧有效查询可用；上游/适配恢复对应版本，受影响数据有核对与修复结果，历史引用保持不变。

这些结果定义预期行为，执行步骤与规则映射见 [验收标准](PS-002-验收标准.md)，当前均未运行。

## 本期边界

一期不承诺免费全市场完整新闻史、全量历史财务修订、逐笔/盘口数据、所有外围市场或无限历史深度。

原方案中超出本期的能力保留为后续候选，不以缩减一期方式删除历史编号。前端、后端和后台任务必须共享相同事实与规则。

## 状态、隐私与恢复

本人数据和导出需认证。新增/修改需明确反馈，失败不覆盖旧有效结果。归档与删除语义按上述规则执行；源数据修订与用户记录版本分离。日志和导出不得包含密钥，外部文本不构成可执行指令。

## 待评审与交接

本稿功能范围和产品建议值待用户确认；数据源实际覆盖、部署配置和性能目标待验证。不得把这些待确认事项改写为已通过。确认后同版本详设应逐条映射规则与验收，不得绕过需求新增自动交易、付费来源或外部通知。
