# PS-002 数据中心 验收标准

需求独立版本：1.0.0。交付批次：V1.0.0。状态：待评审/未执行。

## 场景清单

以下每项都需要实际操作/接口结果及数据证据，不能仅凭截图或模型回答判定成功。使用固定测试数据，账户样本不包含真实凭据。

| 验收 ID | 关联规则 | 操作及数据条件 | 预期结果 |
|---|---|---|---|
| PS-002-AC01 | PS-002-R01 | 用新上市、不足三年和新闻仅短窗口的公司执行首次回补 | 新上市公司不足3年时展示实际覆盖；新闻来源只有短窗口时标记缺口，不伪造30天历史。 |
| PS-002-AC02 | PS-002-R02 | 对一个免费候选和一个需付费权限的候选登记接入状态 | 某候选需要付费权限时标记未启用，不自动付费；来源验证记录可查到数据集和边界。 |
| PS-002-AC03 | PS-002-R03 | 导入同名跨市场证券与手/股两种成交量，再重复同步 | 同名不同市场证券不合并；成交量手/股转换后可核对，重复采集不重复增加日线。 |
| PS-002-AC04 | PS-002-R04 | 导入季度累计财务与后续更正，查询旧快照和单季派生 | 两个季度累计收入不被直接标为单季；后发布更正值不回写旧报告快照。 |
| PS-002-AC05 | PS-002-R05 | 分别模拟周末、正常停牌及交易日超过宽限的数据缺失 | 周末不会仅因未出现当天日线而报警；有效交易日超过配置宽限仍未更新会显示过期。 |
| PS-002-AC06 | PS-002-R06 | 处理损坏PDF、扫描年报和无法抽取的财务表格 | 损坏 PDF 或解析失败不发布空财务值；用户可看到失败原因及仍可用的原文链接。 |
| PS-002-AC07 | PS-002-R07 | 在一批数据提交后中断任务并重启，再制造新闻游标断档 | 任务中断重启后从已保存进度继续；最近窗口不足时产生覆盖缺口提示，不声称历史完整。 |
| PS-002-AC08 | PS-002-R08 | 让主源失败、备用源返回不同复权口径，查看采用记录 | 主源失败时保留旧有效数据并标明时间；不同供应商复权值不能无说明拼成一条曲线。 |
| PS-002-AC09 | PS-002-R09 | 导入各板块名单、同主体多证券及换码样本，执行完整性核对 | 基准日名单中每个当前上市A股证券均有可访问档案或明确异常记录；同一公司不重复建实体，更名换码保留关联。 |
| PS-002-AC10 | PS-002-R10 | 按全A资料目录检查不同类型公司的字段覆盖 | 每家公司有统一资料分类与覆盖状态；缺管理层或股权记录明确显示缺失，不用空白页代替；不采集非公开私人信息。 |
| PS-002-AC11 | PS-002-R11 | 持续加入自选高优先级任务并中断恢复全量回补 | 全市场待补队列有进度且未关注公司仍得到处理；恢复不重复，不能以仅50家公司有数据宣称全量完成。 |
| PS-002-AC12 | PS-002-R12 | 比对官方基准名单，制造缺失上市公司、缺财务和退市转换 | 漏公司使目录验收失败；资料缺失逐项有原因及补齐/范围评审记录；退市后历史仍可查但不出现在当前上市默认列表。 |

## 共性与集成

还必须满足 [一期总览](../../V1.0.0-一期需求总览.md) 的 V1-G01 至 V1-G12 及相关 E2E 流程。来源失败、模型不可用、未登录、重复提交与历史版本至少各保留一项实际证据。涉及数据库锁、幂等与迁移的实现验证必须使用实际 PostgreSQL；纯计算使用固定可复现样本。

执行记录须包含测试输入、预期/实际、通过/失败、失败原因、执行版本和证据路径。当前没有应用，全部未执行；本次文档校验不计为上述业务验收。
