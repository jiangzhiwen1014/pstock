## 目标与场景

让我管理值得研究的公司，并通过可解释条件缩小范围；不把筛选结果包装成买入建议。

## 主流程

搜索证券 → 查看板块与研究用途 → 添加关注原因和分组 → 设置少量筛选条件 → 查看结果与缺失数据 → 手动加入关注 → 跳转公司研究。

入口、跨功能要求及一期容量见 [一期总览](../../V1.0.0-一期需求总览.md)。所有个人投资参数未确认时保持未设置；提到的容量/指标/时刻为产品建议值，不是已知用户事实。

## 数据对象

关注项 ID、证券 ID、分组、关注原因、创建/归档时间、持仓关联；筛选模板 ID、条件版本、计算截至日、有效样本范围。

对象字段为业务语义，物理表、接口路径、错误代码和索引由同版本详设确定。来源、质量与版本语义遵守 [数据架构](../../../architecture/数据架构.md)。

## 业务规则

| 规则 ID | 规则 |
|---|---|
| PS-013-R01 | 支持按代码和名称搜索、添加关注、分组、修改原因、归档及恢复。相同证券不能重复创建关注项，允许属于多个分组。 |
| PS-013-R02 | 持仓公司自动进入持仓关注视图，不需要再次添加；普通关注归档不能屏蔽仍在持仓的公司。清仓后保留历史，用户可决定继续普通关注。 |
| PS-013-R03 | 基础研究筛选默认覆盖全A上市公司，可切换市场/板块或仅看本人可交易的沪深主板。创业板、科创板、北交所可浏览、筛选、对比和关注，但不能被标为本人可执行交易标的；海外等非A股对象另属外围研究。 |
| PS-013-R04 | 一期支持市场/板块、行业、营业收入同比、归母净利润同比、资产负债率和市盈率TTM条件；财务门槛默认未启用，用户明确输入阈值。条件以AND组合，不提供复杂表达式或自动权重。 |
| PS-013-R05 | 筛选字段名称、单位、财报口径和截至时间随结果展示；亏损公司不因负PE被当作低估值。同比基期非正或缺失时不参与增长率门槛判断，标记不可比较。 |
| PS-013-R06 | 保存与修改筛选模板形成版本；结果可按单一已显示字段排序，空值最后，不输出合成买入评分。每次结果显示输入版本、样本数和排除原因。 |
| PS-013-R07 | 列表分页展示，结果可跳转公司档案、加入关注及填写理由；关注容量达到一期配置上限时说明原因，现有持仓不可因额度被静默丢弃。 |
| PS-013-R08 | 首次无数据、没有满足条件、任务未完成和来源失败分别显示；不以接口错误伪装零结果。分组和筛选仅本人可见。 |
| PS-013-R09 | 提供独立的全A公司库入口，默认按当前上市A股展示；支持市场/板块、行业、地区、上市状态、公司名称/代码/历史别名及资料完整度筛选。列表含名称、代码、板块、行业、地区、上市日期、交易权限标识和资料更新时间，证券列表与公司去重计数分别说明。 |
| PS-013-R10 | 公司库、个人关注和持仓为不同视图，关注/取消关注只改变订阅优先级与个人清单，不决定公司能否搜索或查看。全量浏览和基础筛选使用数据库分页，不把全公司资料加载到浏览器或应用内存。 |

## 正常与异常结果

- PS-013-AC01：重复添加同一股票后数量不增加，第二个分组关系保留；归档后可恢复原因和历史。
- PS-013-AC02：归档仍持有的公司时持仓关注入口依然存在；新快照清仓不删除研究历史。
- PS-013-AC03：创业板、科创板与北交所可进入全A研究筛选；切换仅本人可交易时只保留有权限的主板，海外另列外围研究。
- PS-013-AC04：启用两个条件后仅返回同时满足者；清空条件恢复当前市场范围的可用公司列表，不暗中增加默认策略。
- PS-013-AC05：基期亏损转盈利公司不会被错误赋予常规同比排名；缺失字段默认排除于相关条件并计入排除数量。
- PS-013-AC06：相同输入快照和条件版本重算结果相同；空值不出现在升序首位冒充优选。
- PS-013-AC07：满额后新增普通关注有明确反馈，已有关注与持仓均保持完整。
- PS-013-AC08：来源失败显示未完成筛选；成功且无匹配显示0家公司，并保留可调整条件。
- PS-013-AC09：可进入全A所有已建档公司的详情；总数按固定基准日核对，分页/筛选不丢公司，同主体多证券计数不混淆。
- PS-013-AC10：公司资料仍可查看；结果页总数与筛选条件一致且翻页无重复遗漏，资源测试基于全市场数据。

这些结果定义预期行为，执行步骤与规则映射见 [验收标准](PS-013-验收标准.md)，当前均未运行。

## 本期边界

机器学习选股、自动因子挖掘、推荐仓位、买入概率、复杂策略编辑器留待后续；PS-003 策略与评分编号不复用。

原方案中超出本期的能力保留为后续候选，不以缩减一期方式删除历史编号。前端、后端和后台任务必须共享相同事实与规则。

## 状态、隐私与恢复

本人数据和导出需认证。新增/修改需明确反馈，失败不覆盖旧有效结果。归档与删除语义按上述规则执行；源数据修订与用户记录版本分离。日志和导出不得包含密钥，外部文本不构成可执行指令。

## 待评审与交接

本稿功能范围和产品建议值待用户确认；数据源实际覆盖、部署配置和性能目标待验证。不得把这些待确认事项改写为已通过。确认后同版本详设应逐条映射规则与验收，不得绕过需求新增自动交易、付费来源或外部通知。
